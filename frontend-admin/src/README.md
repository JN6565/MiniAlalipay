# B 端源码目录说明

本目录承载运营管理后台的界面与客户端基础设施。页面只能展示服务端授权后的脱敏数据，不能在浏览器中推导资金终态或保存余额、账本等事实数据。

- `layouts`：后台整体布局与导航。
- `pages`：按路由拆分的运营页面。
- `components`：无领域副作用的展示组件。
- `services`：由网关访问后端以及后续生成的 OpenAPI 客户端。
- `stores`：菜单折叠等客户端 UI 状态。
- `utils`：金额和请求编号等无副作用工具。

每个 B 端业务路由使用独立页面目录。OpenAPI 尚未定义的接口不得在本目录中猜测实现；新增业务类型应优先由正式契约生成。

## 状态管理边界

项目按照数据来源和生命周期划分状态管理职责：

| 方案 | 职责 | 示例 |
|---|---|---|
| **TanStack Query** | 管理服务端数据的查询、缓存、失效、重新获取和请求状态 | 运营指标、工单、告警、报表、数据质量结果 |
| **Umi `initialState`** | 保存应用启动时加载的运行时上下文，不作为一般服务端业务数据缓存 | 当前运营身份、登录状态、服务端授予的角色 |
| **Umi `access`** | 根据 `initialState` 中的服务端角色计算前端页面和操作可见性；服务端仍是最终授权方 | 后台准入、只读访问、工单处置权限、演示任务权限 |
| **Zustand** | 保存不属于服务端事实的纯客户端 UI 状态 | 侧栏展开状态、抽屉开关、临时筛选条件 |
| **React 局部状态** | 保存仅在当前组件或页面内部使用的短期交互状态 | 表单输入、弹窗开关、当前选中项 |

选择原则：

- 来自服务端且需要查询、缓存或重新获取的数据，使用 TanStack Query。
- 当前运营身份和角色由 Umi `initialState` 加载，并由 Umi `access` 计算界面权限。
- 纯客户端、跨组件共享的界面状态使用 Zustand。
- 只在当前页面或组件使用的状态优先使用 React 局部状态。
- 禁止在 Zustand、Umi model 或浏览器存储中复制余额、账本事实、交易终态等服务端业务事实。
- 前端权限仅用于界面控制，不能代替网关和后端的身份认证、角色授权及数据范围校验。
